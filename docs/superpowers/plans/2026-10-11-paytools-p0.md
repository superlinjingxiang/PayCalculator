# PayTools P0 Implementation Plan

> **For agentic workers:** Implement task by task and verify each deliverable. Project implementation is already authorized by the user's request.

**Goal:** Deliver a static, local-only Chinese salary calculator with traceable 2026 policy assumptions.

**Architecture:** Pure decimal calculation functions consume validated inputs and month-specific policy data. Client form invokes the functions. App Router pages export static HTML and document the model.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, decimal.js, Vitest, Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-11-paytools-p0-design.md`

**Scope update:** User requested nationwide province/city selection and chose manual local parameters for cities without verified 2026 policies. Add 31 mainland provincial regions and 337 prefecture/direct-admin choices, explicit unverified status, SEO competition research, and static-export browser checks. Only Shanghai has built-in local policy parameters in this version.

## Global Constraints

- Only resident wage income, one employer, tax year 2026.
- No fabricated policy values, production deployment, user-data upload or live ad SDK. Shanghai H1/H2 bases and pension/medical rates have official sources; unemployment continuity is labelled inferred; housing rate must be supplied for each half-year.
- Money uses decimal strings and two-place HALF_UP rounding; rate entries are percentages.
- Static export must produce `out/` and 404, robots and sitemap artifacts.
- Canonical and sitemap URLs require a real configured production URL.

## Review Focus

- A cumulative tax target falling below already withheld tax must not create a negative refund.
- A July Shanghai rule must not affect a June calculation.
- Blank, negative, malformed or oversized currency and rate inputs must be rejected.
- Missing contribution rates must not silently become zero in detailed mode.
- Output identities must hold exactly to the cent with changing monthly wages.
